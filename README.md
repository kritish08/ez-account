# ez-account

Double-entry accounting for small Indian wholesale businesses — invoicing, inventory, payments, GST, and the reports that fall out of a general ledger.

The feature list is not the interesting part. This is a domain where a bug does not throw. It produces a number that is wrong, plausible, and permanent, and every report that reads it inherits the error silently. Most of the engineering here is about making that class of failure detectable.

FastAPI + MongoDB (replica set) · React 19 + Tailwind · Docker Compose behind nginx · 14.7k lines Python, 18k lines JS, 137 backend tests.

---

## What this repository actually is

The first version was generated by an agent platform in January 2026 (`emergent-agent-e1` in the log, auto-commit messages, 28 commits). It ran, it demoed, and a business used it.

Everything after that is the interesting work: reading 20k lines of unfamiliar code that nobody had reviewed, finding what was wrong with it, and proving each finding with a test that failed first. That covers 98 commits — a monolith decomposition, a seven-dimension audit, and the fixes below.

`backend/server.py` peaked at **5,639 lines**. It is now **278**: an app factory, a lifespan, and 23 router includes. The routers are 5,699 lines and the domain services another 1,372.

I mention the provenance because it is visible in `git log` in about fifteen seconds, and because inheriting a working-but-unexamined codebase is the situation most of this work is actually about.

## Three bugs that did not throw

Each of these produced wrong financial statements with no error, no warning, and no log line. Each is now pinned by a test that failed before the fix. The full set is in [`FIXES.md`](FIXES.md) (1,380 lines, one entry per defect with its failure mode).

**Inventory was valued from a field that never existed.** The balance sheet read `p.get("stock")` off product documents. No product document has that key — stock is derived by summing `stock_movements`. `.get()` returned `None`, the sum treated it as zero, and inventory reported **₹0 for every business, in every period, since the feature shipped**. Nothing failed; the report rendered a balance sheet that happened to be missing an asset class.

**Renaming a product silently zeroed its cost.** The update handler typed its request body as `ProductCreate` — a model where `cost_price` defaults to `0` — and then `$set` the whole thing. Correcting a typo in a product name wrote `cost_price: 0`. Every subsequent sale of that SKU posted **COGS of zero** and overstated gross profit, forever, with no way to notice from the UI. The fix is a `ProductUpdate` model plus `model_dump(exclude_unset=True)`; the real bug was a type that made "absent" and "zero" the same value.

**A purchase return credited the wrong account, and the books still balanced.** A purchase debits `inventory_asset`. A return credited `purchases_returns`. Debits equalled credits, so the trial balance tied and every integrity check passed — while the ledger claimed stock the warehouse had physically sent back. The overstatement compounded with every return. This is the example worth dwelling on: **the obvious invariant cannot see it.**

## How correctness is enforced now

One test walks a realistic trading day — buy, sell, collect cash, record an expense, take a sales return, send a purchase return, pay a supplier — and asserts that debits equal credits at all eight checkpoints:

```python
# backend/tests/test_financial.py
async def test_trial_balance_stays_balanced_across_every_write_path(...):
    async def assert_balanced(step: str):
        body = (await http_client.get("/api/reports/trial-balance", ...)).json()
        assert body["is_balanced"] is True, (
            f"unbalanced after {step}: "
            f"debit {body['total_debit']} vs credit {body['total_credit']}"
        )
```

I verified it has teeth by injecting a one-sided entry; it failed and named the step.

**It would not have caught two of the three bugs above.** The debit-note and voice-cash defects both kept debits equal to credits while putting the money in the wrong accounts. An invariant test is a floor, not a proof, and treating a green trial balance as evidence of correct books is exactly the mistake that let these survive. The account-level assertions are what actually catch them.

Test count went from **15 to 137**. Every fix in Phase 1 was written RED first — including one case where I had already written the guard, so I removed it to watch the test fail for the right reason before putting it back.

## Concurrency and money

**Publishing an invoice claims the draft atomically.** The original read the invoice, checked `status == "draft"`, then performed three awaits of ledger and stock writes before flipping the status. Two clicks 50 ms apart both passed the guard: revenue credited twice, stock decremented twice, no error shown to anyone.

```python
invoice = await db.invoices.find_one_and_update(
    {"id": invoice_id, "status": "draft"},
    {"$set": {"status": "publishing"}},
    return_document=ReturnDocument.BEFORE,
)
```

The claim and the check are now the same operation. Because the ledger and stock writes that follow can still fail independently, the handler unwinds both and returns the invoice to `draft` rather than leaving a half-published document. A concurrency test fires two simultaneous publishes and asserts `[200, 400]`.

**Payments run in a real multi-document transaction.** `record_payment` writes a payment, its allocations, and both ledger legs inside one `start_transaction`. Single-node `mongod` rejects that, so local development and CI both run `mongodb-atlas-local` — a single-member replica set — rather than a plain `mongo` image that would silently diverge from production Atlas. The ledger helpers all accept an optional `session=` so callers can enrol their writes in the caller's transaction.

**Money rounds at one place.** `_money()` rounds every per-line value to 2 dp so running totals accumulate already-rounded values. Without it, an invoice of many decimal-priced lines lands on `999.9999999...` and fails a `paid_amount >= total` check by a fraction of a paisa — an invoice that is paid but never marks itself paid.

**GST halves the rounded tax, not the rate.** CGST and SGST are derived by halving the already-rounded total tax rather than rounding each half independently, so the two components always sum back to the tax charged instead of drifting a paisa apart on the printed invoice.

## Security

The audit found no authorization model: 43 endpoints took an ID, two were owner-scoped.

- **Backup restore** — `delete_many({})` then re-insert across every collection — required nothing but a valid session and took *no request body at all*. A test confirmed a `staff` user could factory-reset the company and get a 200. It now takes admin, a password, and a typed confirmation phrase.
- **An unset `CORS_ORIGINS` silently became `allow_origins=["*"]`.** The comment defending it argued the paired `allow_credentials=False` made it safe — but this API authenticates with a header, not cookies, so that flag bought nothing. A missing value is now a boot failure.
- **Logout did not log anyone out.** It deleted the token from `localStorage`; the server never heard. Revocation is now a `jti` denylist plus a per-user `token_version`. The first attempt compared timestamps and failed a test: JWT `iat` has one-second resolution, so it either let through same-second tokens or rejected the user's own immediate re-login. A counter has no such ambiguity.
- **Secrets are encrypted at rest** with AES-256-GCM — envelope encryption with a per-payload DEK for backups, and a tagged `enc.v1:` form for short config values. Untagged values are recognised as pre-encryption plaintext and passed through, because live databases are full of them and a migration that breaks every configured backup is not a security improvement.
- Credentials that were committed to history are removed from HEAD, and CI fails if they reappear. **They remain in history and are not yet purged** — see below.

## Delivery

`React.lazy` and `Suspense` appeared **zero times** across the frontend. All 25 routes shipped in one bundle, so opening `/login` downloaded Reports, Settings, both invoice editors, and a barcode scanner before the password field worked.

| | before | after |
|---|---|---|
| initial JS (gzipped) | 351 KB | **122 KB** |
| chunks | 1 | 42 |
| `html5-qrcode` (106 KB) | every page | first tap on *Scan* |
| source maps in production | served | none |

The trap in that work: `index.html` also loaded the Tailwind CDN compiler, and nine dashboard cards built their colours by string surgery — `` bg-${color.split('-')[1]}-50 `` — which Tailwind's static scanner cannot see and therefore never compiled. Deleting the CDN script first would have silently flattened all nine. The class construction had to be fixed *before* the script came out.

CI runs three jobs on every push: the backend suite against a replica set, a frontend build that **fails if initial JS exceeds 140 KB gzipped** or if source maps or the CDN reappear, and a hygiene job that fails if the credential-bearing files return.

## What is deliberately unfinished

Listed because a reviewer will find them anyway, and because knowing what you did not do is part of the work.

- **No tenant isolation.** Business records carry no owner field and queries are not scoped. Roles are not a substitute. Two businesses on one deployment would see each other's data. This is the largest open item.
- **Committed credentials are still in git history.** Removing them from HEAD does not un-leak a blob. Rotation and a `git filter-repo` pass are pending.
- **GST is issue-side only** — output tax is charged and booked to a liability account, but input credit on purchases is not recorded, so net liability is not yet computable. No GSTR-1/3B export, no e-invoicing.
- **17 of 19 table pages** still render a desktop table on a phone; two were converted to card lists as the pattern.
- **No offline support, no caching layer.** `getProducts()` is called on mount by nine pages, each pulling the full collection.
- **CRA is end-of-life** — 62 build-time advisories with no fix path while `react-scripts@5.0.1` is a dependency. A Vite migration is scoped at 1–2 days.

## Running it

Mongo must be a replica set. `record_payment` opens a transaction and a plain `mongo` image will reject it.

```bash
docker run -d --name ezaccount-cluster -p 27017:27017 \
  quay.io/mongodb/mongodb-atlas-local:latest

cp .env.production.template backend/.env   # JWT_SECRET, MASTER_ENCRYPTION_KEY, CORS_ORIGINS
docker compose up -d --build               # API :8001, UI :8080
```

```bash
cd backend && ./run_tests.sh -q            # 137 tests, in the production image
```

`CORS_ORIGINS` is mandatory — the app refuses to start without it, by design. The OpenAI key is optional: AI features (bill scanning from a photo, a Hindi/English voice assistant) degrade to a 503 that names the setting, and the accounting application is unaffected. A key is supplied through Settings → AI, encrypted at rest, and can be replaced without a redeploy.
